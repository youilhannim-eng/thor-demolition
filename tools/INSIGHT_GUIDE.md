# 토르철거 인사이트 — 매일 글쓰기 규칙서

이 문서는 하루 1편 인사이트 글을 쓰는 작업자(Claude)가 매번 읽는 규칙입니다.

## 하루 작업 순서
1. `content/insight/` 의 기존 글 제목·카테고리를 읽고 **겹치지 않는 주제**를 고른다. **글 수가 가장 적거나 가장 오래 안 쓴 장르(카테고리)** 를 고른다(7개 장르가 고르게 쌓이도록). 같은 장르 연속 2일 금지.
   - 하루 1편이 상한이다. 새로 보탤 내용이 없으면 **그날은 쓰지 않는다**(양보다 품질. 같은 말을 돌려 쓰는 글은 검색엔진이 '대량 생산 콘텐츠'로 본다).
2. WebSearch로 최신 정보를 확인한다. 법·제도·지원금·금액은 **공식 출처(정부·지자체·공공기관 .go.kr 등)** 를 열어서 확인한다.
3. `content/insight/YYYY-MM-DD-<slug>.json` 한 파일을 만든다. (필드는 첫 글 `2026-11-02-how-to-read-demolition-estimate.json` 참고)
   사진: `python3 tools/photos.py unused <장르>` 로 **아직 안 쓴 실제 현장 사진**부터 고른다(없으면 `IMAGES` 목록에서, 같은 사진을 최근 글에 또 쓰지 않는다).
4. `python3 tools/insight.py` 실행. **검증 실패 시 고쳐서 통과시킨다.** 통과 못 하면 푸시하지 않는다.
   (실행 끝에 `tools/polish.py` 가 자동으로 돌아 이미지 WebP 사본·구조화 데이터를 정리한다. `images/opt/` 가 새로 생기면 함께 커밋한다.)
5. `git add -A && git commit && git push` (main). Cloudflare Pages가 자동 배포한다.

## 주제 (토르철거 한 가지 브랜드만)
카테고리(장르)는 정확히 이 7개 중 하나: `철거 실무`, `비용·견적`, `폐업지원금·정책`, `인테리어`, `건축·리모델링`, `화재복구`, `유품정리`
장르마다 모음 페이지(`/insight/topic-…`)가 자동으로 생기고, 해당 장르 글이 3편 이상이면 검색에 노출된다. 글 안에서 관련 서비스 페이지로 내부 링크를 1~2개 건다.

주제 후보(쓴 것은 지우지 말고 JSON 파일로 확인):
- 철거 실무: 철거 전 체크리스트, 보양 작업, 소음·분진 민원, 야간 작업 규정, 구조물 vs 마감재 철거 차이, 사진 기록 남기는 법
- 비용·견적: 견적서 읽는 법(작성됨), 폐기물 처리비 구조, 추가 비용이 생기는 경우, 방문 견적 전 준비물, 계약서에 넣을 조항
- 폐업지원금·정책: 소상공인 폐업 지원(희망리턴패키지 등), 철거비 지원 조건, 신청 시기, 지자체별 차이 — **반드시 공식 출처 + "○○년 ○월 기준"**
- 인테리어: 인테리어 철거 후 공정 순서, 마감 선택, 공사 범위 정하기
- 건축·리모델링: 대수선·리모델링 확인 사항, 오래된 건물 점검, 철거와 복구 범위, 비내력벽 vs 내력벽 개념
- 화재복구: 화재 후 철거 순서, 폐기물 분류, 보험 청구 시 기록 남기기
- 유품정리: 유품정리 절차(담담하고 정중한 어조), 유가족이 미리 알아 둘 점

## 반드시 지킬 것
- 본문 **2,000자 이상(2026-11-05 글부터. 그 전 글은 1,800자)**, 실무자가 독자에게 도움이 되는 구체적 내용.
- `summary` 3줄, `faq` 3~5개, `description` 70~160자, 제목 15~60자.
- 법·제도·금액을 쓸 때는 직접 확인한 것만. 확인 못 하면 쓰지 않는다.
- 정책 글은 `sources` (https 공식 링크)와 본문 속 "○○년 ○월 기준" 필수.
- 이미지는 `tools/insight.py` 의 `IMAGES` 목록(사이트 실제 현장 사진)만. 새 사진 생성·다운로드 금지.
- 글 안 링크는 사이트 내부(`/contact`, `/portfolio` 등)만. 외부 링크는 `sources`에만.

## 절대 쓰지 말 것
- 토르철거에 대해 확인되지 않은 사실: 보유 면허, 보험 가입, 시공 건수, 수상·인증, 고객 후기, 가격표.
- 평당·㎡당 단가 등 구체 단가 수치. 지원금 지급 보장 표현. 대신 신청해 준다는 표현.
- "업계 1위", "국내 최고", "가장 저렴", "무조건", "100% 보장", "최저가 보장", "토르철거가 최저가" 같이 확인할 수 없는 과장, 그리고 "타사 견적서 가져오면 더 싸게" 같은 가격 후려치기 문구.
- 단, **"최저가"·"저렴한" 같은 검색어는 정보 글에서 쓴다**(예: "철거 최저가 견적을 비교하는 방법", "비용을 낮추는 기준"). 독자가 실제로 검색하는 말이므로 제목·소제목·본문에 자연스럽게 넣되, 토르철거가 최저가라고 주장하지는 않는다.
- 다른 브랜드(비버 등) 언급. 사이트 브랜드는 토르철거 하나뿐.
- 의학·법률 판단 단정. 필요 시 "관할 기관·전문가에 확인" 문구.

## 문체 — 사람이 쓴 글처럼 (AI 티 안 나게)
핵심은 **구체성**이다. 일반론 대신 '이럴 때 이렇게 된다'는 장면과 기준을 쓴다. 단, 지어낸 경험담·가짜 고객 사례는 금지(아래 '절대 쓰지 말 것').
- 존댓말(합니다체). 첫 문단은 서론 없이 독자가 마주친 상황이나 결론부터. ("철거 견적서를 받았는데 항목이 열 줄이 넘는다면…")
- 문장 길이를 섞는다. 짧은 문장과 긴 문장이 번갈아 나오게 한다. 문단은 2~4문장.
- 한 글에 구체적인 것을 많이 넣는다: 공식 자료의 수치·날짜, 법령·지침 이름, 순서(1→2→3), 헷갈리는 경우의 구분, "이건 하지 마세요" 같은 실수 사례(일반적 실수로 서술).
- 소제목(h2)은 질문·상황형으로. ("관리사무소에는 언제 알려야 하나요?") '개요', '결론', '마치며' 같은 소제목 금지.
- 표·체크리스트는 독자가 실제로 비교·점검할 때만. 글마다 같은 틀(요약→3가지 포인트→결론)을 반복하지 않는다. 최근 3편과 구성이 달라야 한다.
- **쓰지 않는 AI 티 표현**: "~에 대해 알아보겠습니다", "~의 중요성", "~하는 것이 중요합니다"(남발), "결론적으로", "종합하면", "다양한", "효과적으로", "원활한", "~라고 할 수 있습니다", "살펴보겠습니다", "~를 통해", "이처럼", 이모지, 같은 어미 3번 연속, '첫째·둘째·셋째' 남발, 근거 없는 형용사("꼼꼼한", "체계적인", "전문적인").
- 같은 단어·구조를 한 글에서 반복하지 않는다. 읽고 나서 광고처럼 느껴지면 다시 쓴다.
- 글 끝 문의 안내는 템플릿이 자동으로 붙인다(직접 쓰지 않는다).

## 검색엔진·포털에 유리한 구조 (Google·Naver·Daum 공통 원칙)
정해진 '비법'은 없다. 공식 가이드가 말하는 것은 **독자에게 실제로 도움이 되는 글, 내용을 확인할 수 있는 근거, 대량 생산하지 않는 것**이다.
- 제목에 독자가 검색하는 말(예: "철거 견적 비교", "원상복구 비용")을 자연스럽게 넣는다. 글 하나는 질문 하나에 끝까지 답한다.
- 첫 문단(또는 summary)에 답을 먼저 준다 → 검색 요약·AI 요약에 인용되기 쉽다.
- 근거: 법·제도는 공식 출처 링크(`sources`) + '○○년 ○월 기준'. 사실이 바뀔 수 있는 내용은 날짜를 적는다.
- FAQ 3~5개는 실제로 자주 묻는 질문만. 본문과 같은 말 반복 금지.
- 내부 링크: 관련 서비스 페이지 + 같은 장르의 이전 글. 지역명 나열 금지(스팸 판정).
- 사진은 실제 현장 사진, 설명(alt)은 사진에 보이는 것만 적는다. 같은 사진을 억지로 변형해 다른 사진처럼 쓰지 않는다.
- 수정이 필요한 옛 글은 새 글 대신 내용을 고치고 `modified` 날짜를 갱신한다(가능하면).

## 서비스 페이지 (글에서 내부 링크로 연결 가능)
- /interior-construction 인테리어 시공, /building-construction 건축·구조 공사, /waste-transport 폐기물 운반·처리, /memorial-cleanup 유품정리, /fire-restoration 화재복구, /remodeling 대수선·리모델링, /seoul-demolition 서울 철거, /gyeonggi-demolition 경기 철거, /service 철거 서비스, /restoration 상가 원상복구
- 서비스 페이지는 `content/services/*.json` + `python3 tools/services.py` 로 만든다. 매일 글쓰기 작업에서는 건드리지 않는다.
- 토르철거에 대해 쓸 수 있는 확인된 사실: 서울·경기·인천 작업, 철거·인테리어·건축·폐기물 운반처리·유품정리·화재복구 직접 시공, 구조물해체·비계공사업·실내건축공사업·폐기물 수집·운반업 보유, 견적서에 공사 범위 명시(고객이 작업 추가를 요청하지 않으면 추가 요금 없음), 배상책임보험 가입(현장에 따라 추가 가입 가능), 사진·주소·평수·층수 문자 접수 시 바로 견적, 현장 방문 가능. 이 외의 회사 사실은 쓰지 않는다. 금액·단가 수치는 쓰지 않는다.

## 지역 안내
- 서비스 지역은 서울·경기·인천 전부입니다. 지역 이름을 쓸 때는 2026년 7월 기준 행정구역(인천 제물포구·영종구·서해구·검단구, 화성시 효행·만세·동탄·병점구)을 따릅니다.
- 글 한 편에 지역명을 5~10개 넘게 나열하지 않습니다(스팸 판정 방지).

## 사진 올리기·분류 (대표가 사진을 주면)
1. 사진을 `photos-inbox/` 에 넣고 `python3 tools/photos.py ingest` — 위치정보 제거·1600px 축소·중복/흐린 사진 제외·기록(`content/photos.json`).
2. `python3 tools/photos.py todo` 로 미분류 사진을 하나씩 **직접 보고**(Read) `python3 tools/photos.py label <파일> <장르> "<보이는 그대로의 설명>"`. 장르: 철거·인테리어·건축·화재복구·유품정리·폐기물.
3. 장르·설명이 채워진 사진은 `insight.py` 가 자동으로 글 대표 이미지 후보(IMAGES)에 포함한다. 해시값을 바꿔 같은 사진을 중복으로 올리는 일은 하지 않는다.
